# Arm results, in the order the paper should use

Generated by `grid/arms/analysis_arms.py`. **Do not hand edit**: it is overwritten on every run. Every number below is in a CSV or JSON beside this file, and section 8 says which.

The order is deliberate. The control comes first because it explains WHY transfer fails, and everything after is read against it.

## 1. The LoHi internal control. The yardstick

Annotation protocol, annotators, class list and production line are all held constant. Only the acquisition changes. This is the one measurement in the study that isolates visual domain shift with the label concept pinned, so it is the number every cross-dataset figure should be read against.

| train | to lohi_high | to lohi_low |
|---|---|---|
| lohi_high | 0.6539 (0.028) | 0.2402 (0.044) |
| lohi_low | 0.3031 (0.029) | 0.6730 (0.023) |

- lohi_high->lohi_low: **T = 0.357**, 95 percent split block interval [0.236, 0.498]
- lohi_low->lohi_high: **T = 0.463**, 95 percent split block interval [0.371, 0.659]

**Interpretation, with its confound attached.** Changing only the acquisition still costs roughly half of box mAP50. So visual shift alone causes a large collapse. But the defect mix ALSO differs sharply between the two acquisitions, pore 5.5 percent of high resolution boxes against 26.5 percent of low, deposit 18.9 against 8.8, the project log 7. This is not pure sensor shift. Part of it is prior shift. Both halves belong in the caption.

**Image AP is uninformative here and must not be quoted.** It is 0.99 to 1.00 in every cell because LoHi is 97.6 percent positive. The control is a box level result.

**Precedent.** LoHi-WELD's own IEEE Access 2024 description runs the same internal test across its two acquisitions. This version differs by running under the leakage audited splits and the same protocol as the rest of the study. Cite it as precedent, not as novelty.

Table `lohi_control.md`, intervals `lohi_control_transfer_intervals.csv`, figure `lohi_control_matrix.pdf`.

## 2. The box level cross-dataset matrix

Source: `grid_results/analysis/tables/transfer_box_*.md`, one table per configuration, with split block intervals in `transfer_ratio_intervals.md`.

**Two training rows, not three.** Only `kaggle_v2` and `lohi_weld` use a localisation protocol and are large enough to train on. `weld_surface_v2` annotates a frame sized quality verdict, so it cannot be a box level training row or target column. That the public visible light data supports only two localisation training rows is itself a finding, the project log finding 3.

**The main grid is unaffected by the the project log 6a-iii class space defect**, because a main grid model predicts in its own source space and is filtered with source ids, which is correct. The defect was specific to arm B, whose head is rebuilt at the target `nc`.

Read section 1 against this. The control's internal collapse is the floor that visual shift alone explains. Whatever the cross-dataset matrix loses beyond that is attributable to the other axes, object scale and annotation protocol.

## 3. The base-rate corrected image level matrix

Source: `grid_results/analysis/tables/transfer_image_*.md` with `target_base_rates.csv`.

**Always the base-rate corrected form.** Positive class AP is floored by prevalence, so a raw image AP of 0.99 on a 97.6 percent positive target is a statement about the target, not about the model. The project log 5k measured LoHi's entire available headroom at 0.0243 and the four configurations take 88 to 97 percent of it.

**AUROC is reportable on two targets only**, `kaggle_v2` and `weld_surface_v2`, plus the LoHi low resolution verdict subset. The other three have too few negative images, so AUROC is returned as null with a stated reason rather than as a number a reader would trust. The project log 5 and 5d. **This is why the false positive budget metric in section 6 carries the inspection claim, not AUROC.**

**NEVER POOL R ACROSS PAIRS.** The denominators span roughly a factor of nine, so a pooled mean of ratios is not a quantity. Report per pair and per configuration, always with the absolute AP beside it, which is why both are in the table above.

**Any ratio into `twoclass` must be quoted with its reference score.** twoclass's reference is weak by construction, 213 training images over 23 scene blocks and 7 joint configurations, the project log 5b. A ratio at or above 1 there says the denominator is small, not that transfer is superb.

**The two hard targets are `visual` and `kaggle_v2`**, whose own in domain box AP is near 0.1. The project log 5n diagnoses kaggle_v2 four ways: not a mapping fault, not object scale, not resolution, but a generalisation failure from 745 `Defect` boxes across 337 images. Their absolute numbers stay small even at a respectable R, which is the reason the absolute AP is printed.

**Plotted against the REALISED scene count, as points**, never against requested k and never joined into a line across draws. The project log 6a-i: a split block is indivisible, so a draw can overshoot k by up to 9.1 times. The requested k is a sampling instruction, not a measured quantity.

**Box level curves exist for six pairs, image level for eight.** Every pair into `weld_surface_v2` is box undefined by protocol.

**The detection head is reinitialised at every k**, the project log 6a-iv, because the source and target class counts differ. Backbone and neck carry over and the head does not, which is now asserted rather than assumed: `train_arm` records `head_nc` and `target_nc` in every `cell.json` and fails the cell if they disagree. So arm B measures the target annotation budget needed to fit a NEW head on a source pretrained backbone. That is what a practitioner adopting a public checkpoint faces, so it is the useful quantity as well as the honest description. Say it in the caption, not only the methods.

**8 of 240 box defined records retain no prediction at all at the primary `last` endpoint**, and 9 of 240 at `best`, 17 across both. All are at the smallest budgets. The reinitialised head has collapsed onto a single wrong class, emitting its full detection cap in classes that are not the defect class. The project log 6a-v: this is a result about fitting a head on a small draw, NOT a class space fault, and the cells stay in every table, flagged. Box mAP50 of 0.0 is the correct value; image AP is suppressed to null there, because an all tied score vector is undefined rather than zero.

**WHICH TEN IMAGES YOU DRAW MATTERS MORE THAN THE SCHEDULE, on a small target.** The project log 6a-xvii. At k = 10 the three draws span 1.7x on `lohi_weld` but **16.1x on `twoclass`**, whose train split holds 213 images over 23 scene blocks. That spread is larger than any schedule effect measured here. So on a small, low scene count target, what a practitioner gets for ten annotated images depends more on WHICH ten than on anything else this study varied. Report every cell per draw, as points, never as a pooled mean alone.

Figures `armb_recovery_box_last.pdf` and `armb_recovery_image_last.pdf`, table `armb_recovery.md`, every cell in `armb_recovery.csv`.

### 4a. Two EXPLORATORY controls on the curve's shape

**Neither is pre-registered, and `ARMB_EPOCHS` stays at 50.** The project log 6a-xii records that as a decision: the schedule was fixed a priori, and changing it after seeing a result is what pre-registration exists to prevent. These explain the curve's shape. They are a discussion result, not the headline, and their exploratory status belongs in the text AND the caption.

At k = 10 the step budget is about 100 optimisation steps against 1,600 at k = 250, so a low score at small k could be too few labels or too few steps. Two controls separate them, on `kaggle_v2` to `lohi_weld`:

| arm | distinct images | steps | cosine over | close_mosaic |
|---|---|---|---|---|
| A fixed 50 | 10 | 100 | 50 epochs | 20% |
| B oversampled 50 | 10 | 1,650 | 50 epochs | 20% |
| C matched step | 10 | 1,600 | 800 epochs | 1.25% |

**The step count is the driver.** A to B, which changes only the step count, is +0.1656 box mAP50 at k = 10 and +0.1531 at k = 50. B to C, which changes only the schedule shape, is +0.0379 at k = 10 and **-0.0206** at k = 50. The schedule term does not hold its sign across the two coordinates, so no single percentage is quoted. The project log 6a-xi and 6a-xiv.

So the small-k floor is an optimisation BUDGET limit rather than a label limit. Recovery on that pair goes R = 0.102 at the pre-registered schedule to **R = 0.347** with the step budget matched under the same schedule shape. **Quote 0.347**, because it changes exactly one thing against the pre-registered arm.

**Target headroom does not explain which pairs respond.** Holding the source at `kaggle_v2` and varying only the target, delta R is +0.2464 into `lohi_weld`, +0.2487 into `twoclass` and +0.1148 into `visual`, against in domain scores of 0.688, 0.528 and 0.142. `twoclass` has three quarters of `lohi_weld`'s headroom and an almost identical response. Predictions were written down before those cells ran, and one was confirmed and one refuted. The project log 6a-xvi.

**`visual`'s response is real and tiny**, 0.0000 to 0.0153 box mAP50. A delta R of 0.115 built on a 0.0153 absolute gain must not be read as `visual` behaving like `lohi_weld`.

**One cell is unexplained and is stated as a limitation.** `lohi_weld` to `kaggle_v2` responds at +0.0221, five times below the weakest of the above. That cell differs in BOTH source and target and the experiment held the source fixed, so the two were not separated. The project log 5n's diagnosis of `kaggle_v2` as a hard target is the candidate. The project log 6a-xviii records the decision not to run the six further cells, because `twoclass` already spans sixteenfold across draws and they could not separate a source effect from draw identity.

Tables in `grid_results_msc/matched_step_control.md` and `.csv`.

## 5. Arm D, leave one dataset out

**Pooling does not reliably help.** Each pooled fold is compared against the best single POOL MEMBER at the same family and seed, which holds the training budget fixed: the pool contains exactly those members, so this is one training set against itself pooled or not. Pooling wins **36 of 108** cell level comparisons.

**Arm D cannot report a box level number for any held out training source.** Derived from `config_arms.box_level_defined`, not asserted: `box_defined_on_any_held_out_training_source` is `False`. Two exclusions compose. A pool containing `weld_surface_v2` is protocol mixed, and the one localisation pool is held out against `weld_surface_v2`, which is whole region. Its box level evidence is therefore only `pool_no_weld_surface_v2 to twoclass`, `pool_no_weld_surface_v2 to visual`. Say this in the caption, or a reader will assume a run failed.

**The honest limit of the design.** Three training sources means a fold trains on two, so this is leave one out over a very small pool count and a weak test of whether breadth helps. It does not license a claim that pooling never helps, only that two-source pooling did not help here. The project log 6b and 6b-ii.

Table `armd.md`, coverage `armd_box_limit.json`.

## 6. Recall at a fixed false positive budget

Table `recall_at_fp_budget_arms.md`, CSV `recall_at_fp_budget_arms.csv`. Reported at 0.1, 0.5 and 1.0 false positive boxes per image, throughout.

**This metric carries the inspection claim, not AUROC.** Inspection requirements are specified as a recall at a tolerated false alarm rate, no weld detection paper reports it, and it stays measurable on all five targets because it counts false positive BOXES rather than false positive IMAGES. Three of five targets have too few negative images for AUROC. The project log 5.

## 7. Calibration under shift

Table `calibration_arms.md`, per bin data for the reliability diagrams in `reliability_bins_arms.csv`.

**Calibration degrades under shift, and the control shows it cleanly.** Inside the LoHi control, where everything but the acquisition is held constant, mean ECE rises from 0.198 in domain to 0.333 cross acquisition. Arm B's fine tuned models are the worst calibrated in the study, at a mean of 0.532 over 240 cells.

**The error runs towards underconfidence, not overconfidence.** 48 of 48 control evaluations, 240 of 240 fine tuned models and 105 of 108 pooling evaluations score the defective images below their share, weighted by image count over the bins. A reinitialised head fitted on a handful of images (the project log 6a-iv and 6a-v) scores the target's defective images low, and under the shift the scores fall while the share of images with a defect stays near one. **A threshold carried over from the source domain therefore misses defects, and for an inspection claim that matters more than the mAP does.** Figure 4.4, `reliability_control.png`, shows it inside the control.

On a target where nearly every image carries a defect, calibration error mostly measures how far the scores sit below that share, so read cross domain rows against in domain rows of the same arm rather than against an absolute standard.

## Per class AP

**Never printed without its test instance count**, and classes below 50 test instances are marked thin. Four classes are thin in the frozen splits, concentrated in the two smallest sources. A thin class needs a split block bootstrap interval, not seed dispersion: the project log 5m measured twoclass `Geometric defect` at seed SD 0.066 against a split block interval of [0.025, 0.675], roughly five times wider.

The arms contribute no per class table, because `evaluate_arm.py` writes per class AP only in domain and the arms are cross acquisition or cross dataset throughout. See `per_class_arms.md`, which reports the absence rather than an empty table. The in domain table is the main grid's, `grid_results/analysis/tables/per_class_ap.md`.

## Statistics, pre-registered and exploratory separated

**Pre-registered**, decided before any result existed: Friedman blocked on evaluation cell with Nemenyi post hoc as primary, RM-ANOVA with Tukey as secondary, split block bootstrap for the transfer ratio intervals.

- main grid Friedman: p = 0.257 image level, p = 0.789 box level
- arms Friedman, box level, 6 blocks: p = **0.5724**
- the arms agree that architecture does not rescue transfer: **True**

**Six blocks is thin and a null there is uninformative rather than confirmatory.** The main grid's 15 block test carries the pre-registered claim.

**Mean rank direction must be stated beside every rank table.** `stats_tests.nemenyi` uses `scipy.stats.rankdata`, which ranks ascending, so rank 1 is the SMALLEST value. Every metric here is one where larger is better, so a HIGHER mean rank is the better configuration. The project log 6a-vii: an earlier draft had this backwards and would have named the worst configuration as the best.

**The architecture question, reconciled.** Mean arm B box mAP50 is RT-DETR-l 0.0926, YOLO11s 0.0941, under 2 percent apart. An earlier VOID run showed a factor of nine, and that gap was an artefact of training from random initialisation, where RT-DETR converges far slower than YOLO. With the checkpoints actually loaded the two are indistinguishable, which is CONSISTENT with the main grid's Friedman null rather than in tension with it. The project log 6a-xiii.

**Exploratory, NOT pre-registered.** A Friedman across the five k levels is a reasonable question and was not pre-registered; the pre-registered test was about configurations.

- k level Friedman, 36 blocks: p = **1.238e-21**

**A significant k effect is not the same as a useful one.** A rank test detects ordering, not magnitude. Quote the recovery numbers in section 4, never this p value.

Details in `stats_arms.md` and `stats_arms.json`.
